Build PixelLab — Interactive Computer Graphics Algorithm Visualizer

Create a polished, interactive website called PixelLab that helps college students understand Computer Graphics (CG) algorithms through visual demonstrations and step-by-step animations.

1. Design and Interface

Use a modern, dark-themed interface inspired by pixel art and graphics development tools.

- Dark charcoal background with subtle grid patterns.
- Cyan, purple, and green accents.
- Clean typography, rounded panels, and restrained animations.
- A left sidebar for selecting algorithms.
- A large central coordinate-grid canvas.
- A right panel displaying inputs, calculations, and explanations.
- Playback controls below the canvas.

Keep the design visually engaging but functional. The graphics canvas should be the main focus, not text or decorative cards. Make the layout responsive and easy to use on desktop and mobile.

2. Implement These Algorithms

Line Drawing

- DDA Line Drawing Algorithm
- Bresenham's Line Drawing Algorithm

Let users enter endpoints, visualize the line pixel by pixel, inspect intermediate calculations, and compare both algorithms using identical inputs.

Circle Drawing

- Midpoint Circle Drawing Algorithm

Let users specify the centre and radius. Animate circle construction and highlight the eight symmetric points at each step.

2D Transformations

- Translation
- Rotation
- Scaling
- Reflection

Allow users to select a triangle or rectangle, modify transformation parameters, and compare the original shape with the transformed shape. Display the updated coordinates and relevant transformation matrices.

Line Clipping

- Cohen–Sutherland Line Clipping Algorithm

Allow users to enter a line and adjust a rectangular clipping window. Display endpoint region codes and animate the process of accepting, rejecting, or clipping the line.

3. Interactive Visualization

Every algorithm should support the relevant controls:

- Visualize — Start the demonstration.
- Play/Pause — Control the animation.
- Next Step — Advance one step at a time.
- Reset — Restart the demonstration.
- Speed — Adjust the animation speed.

Users must be able to change inputs and rerun algorithms without refreshing the page.

Show a coordinate grid, labelled axes, and clearly highlighted pixels or geometric objects. Correctly map mathematical coordinates to screen coordinates.

4. Learning Panel

Display concise, contextual information for the selected algorithm:

- What the algorithm does.
- Input parameters.
- Relevant formulas.
- Current iteration and intermediate calculations.
- Current pixel coordinates or transformation state.

Update the panel as the animation progresses so users can connect the calculations to the visual result.

5. Algorithm Comparison

Create a comparison mode for DDA and Bresenham.

Allow users to:

- Enter one set of endpoints.
- View both algorithms side by side.
- Compare their generated pixels and iteration counts.
- Inspect their different calculation methods.

If execution time is included, measure it separately and explain that it may vary between runs.

6. Quality Requirements

- Implement the actual algorithms rather than drawing only their final results.
- Keep calculations separate from visualization and interface code.
- Handle negative coordinates, steep slopes, reversed endpoints, and invalid inputs appropriately.
- Ensure all controls work correctly.
- Avoid placeholder buttons and simulated calculations.
- Include useful default examples so users can explore the website immediately.
- Test each algorithm with multiple inputs.
- Keep the code organized and include a README with setup and usage instructions.

7. Development Priority

Build the website in stages:

1. Create the interface and interactive coordinate grid.
2. Implement and test DDA and Bresenham.
3. Add Midpoint Circle.
4. Add 2D transformations.
5. Add Cohen–Sutherland clipping.
6. Add comparison mode and polish the interface.

Choose the most suitable technology stack and implementation approach yourself. Prioritize correctness, interactive learning, and a polished user experience.

Final goal: Deliver a fully functional website where users can experiment with fundamental Computer Graphics algorithms and understand how each algorithm works by watching it execute.
